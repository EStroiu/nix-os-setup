# NixOS Configuration

Personal NixOS configuration managed with **Nix flakes**, **Home Manager**, **Niri**, and Git.

The repository is designed so that:

* machine-specific configuration lives under `hosts/`;
* reusable system configuration lives under `modules/`;
* user configuration lives under `home/`;
* hardware configuration stays specific to each machine;
* the same shared configuration can be reused on additional laptops later.

## Repository structure

```text
nixos-config/
├── flake.nix
├── flake.lock
├── README.md
│
├── hosts/
│   └── personal-laptop-nixos/
│       ├── configuration.nix
│       └── hardware-configuration.nix
│
├── modules/
│   ├── common.nix
│   ├── desktop.nix
│   ├── maintenance.nix
│   ├── niri.nix
│   ├── ssh.nix
│   └── wireguard.nix
│
└── home/
    └── remarka/
        ├── home.nix
        └── niri/
            └── config.kdl
```

## How the configuration is organised

### `flake.nix`

`flake.nix` is the entry point of the configuration.

It defines:

* the Nixpkgs version used by the system;
* Home Manager;
* each NixOS machine managed by this repository.

For example:

```nix
nixosConfigurations.personal-laptop-nixos = ...
```

represents the current laptop.

`flake.lock` pins exact dependency revisions. It should be committed to Git.

---

## `hosts/`

Each physical machine gets its own directory.

For example:

```text
hosts/
└── personal-laptop-nixos/
```

The machine-specific directory contains:

### `configuration.nix`

Contains configuration specific to that computer, such as:

* hostname;
* bootloader;
* user account;
* imported shared modules;
* system state version.

It should stay relatively small.

### `hardware-configuration.nix`

Generated by NixOS based on the hardware and filesystem layout of that particular machine.

This file should normally **not be copied from one computer to another**.

Each new machine should generate its own version.

---

## `modules/`

These are reusable NixOS system modules.

### `common.nix`

Settings shared across machines, including things such as:

* Nix flakes;
* NetworkManager;
* locale;
* timezone;
* common system tools;
* Fish;
* unfree package support.

### `desktop.nix`

General graphical desktop functionality.

Currently includes GNOME as a fallback desktop, PipeWire, printing, keyboard configuration, and other graphical-system settings.

GNOME is intentionally kept available while Niri is the main desktop.

### `niri.nix`

Enables the Niri Wayland compositor and system-level components required by the Niri session.

The actual Niri keybindings and layout configuration are kept under Home Manager.

### `maintenance.nix`

Automatic Nix maintenance, including:

* garbage collection;
* deletion of sufficiently old generations;
* Nix store optimisation.

The systemd-boot configuration also limits the number of generations displayed in the boot menu.

### `ssh.nix`

Enables the OpenSSH server.

### `wireguard.nix`

Installs WireGuard tooling.

Actual private VPN configuration should not be committed to this repository.

---

## `home/`

This directory contains user-level configuration managed through Home Manager.

Current user:

```text
home/remarka/
```

### `home.nix`

Manages the personal environment, such as:

* Fish shell configuration;
* Starship prompt;
* Kitty terminal;
* Git configuration;
* command-line tools;
* Fuzzel;
* Waybar;
* Mako;
* Swaylock.

System services belong in NixOS modules. Personal applications and shell configuration generally belong here.

### `niri/config.kdl`

Contains the Niri user configuration:

* keyboard shortcuts;
* workspace navigation;
* column navigation;
* stacked-window controls;
* resizing;
* Noctalia integration;
* monitor shortcuts;
* overview;
* terminal launcher.

Home Manager installs this file as:

```text
~/.config/niri/config.kdl
```

# Normal workflow

After editing configuration files:

```fish
cd ~/nixos-config
git add .
nix flake check
rebuild
```

`rebuild` is a Fish alias for:

```fish
sudo nixos-rebuild switch --flake ~/nixos-config#personal-laptop-nixos
```

After confirming that the new configuration works:

```fish
git status
git commit -m "Describe the change"
git push
```

New files should always be added to Git before running Nix commands:

```fish
git add .
```

Git-backed flakes cannot see untracked files.

---

# Updating NixOS and Home Manager

Update the flake inputs with:

```fish
cd ~/nixos-config
nix flake update
```

Then check the configuration:

```fish
git add .
nix flake check
```

Build and activate it:

```fish
rebuild
```

After verifying that everything works:

```fish
git add .
git commit -m "Update flake inputs"
git push
```

Keeping `flake.lock` in Git means every system update is recorded and can be rolled back through Git if necessary.

# Adding another NixOS machine

Suppose the new laptop will be called:

```text
work-laptop-nixos
```

## 1. Install NixOS normally

Perform a normal NixOS installation first.

Make sure the machine boots successfully before replacing its configuration with this repository.

## 2. Clone this repository

```fish
git clone git@github.com:EStroiu/nix-os-setup.git ~/nixos-config
cd ~/nixos-config
```

If flakes are not yet enabled on the fresh installation, they may need to be enabled temporarily when performing the first rebuild.

## 3. Create a host directory

```fish
mkdir -p hosts/work-laptop-nixos
```

## 4. Copy the new machine's hardware configuration

Use the `hardware-configuration.nix` generated during installation:

```fish
sudo cp /etc/nixos/hardware-configuration.nix \
  ~/nixos-config/hosts/work-laptop-nixos/hardware-configuration.nix
```

Fix ownership if necessary:

```fish
sudo chown "$USER":"$(id -gn)" \
  ~/nixos-config/hosts/work-laptop-nixos/hardware-configuration.nix
```

Do **not** reuse:

```text
hosts/personal-laptop-nixos/hardware-configuration.nix
```

on another machine.

## 5. Create the new host configuration

Create:

```fish
nano hosts/work-laptop-nixos/configuration.nix
```

A basic host can reuse the existing shared modules:

```nix
{ pkgs, ... }:

{
  imports = [
    ./hardware-configuration.nix

    ../../modules/common.nix
    ../../modules/desktop.nix
    ../../modules/niri.nix
    ../../modules/maintenance.nix
    ../../modules/ssh.nix
    ../../modules/wireguard.nix
  ];

  boot.loader.systemd-boot = {
    enable = true;
    configurationLimit = 10;
  };

  boot.loader.efi.canTouchEfiVariables = true;

  networking.hostName = "work-laptop-nixos";

  users.users.remarka = {
    isNormalUser = true;
    description = "Elena Stroiu";

    extraGroups = [
      "networkmanager"
      "wheel"
    ];

    shell = pkgs.fish;
  };

  home-manager = {
    useGlobalPkgs = true;
    useUserPackages = true;

    users.remarka = import ../../home/remarka/home.nix;
  };

  system.stateVersion = "26.05";
}
```

Some settings may need to differ depending on the hardware.

## 6. Add the host to `flake.nix`

Add another NixOS configuration:

```nix
nixosConfigurations.work-laptop-nixos = nixpkgs.lib.nixosSystem {
  system = "x86_64-linux";

  modules = [
    ./hosts/work-laptop-nixos/configuration.nix
    home-manager.nixosModules.home-manager
  ];
};
```

The repository can then contain multiple machines:

```text
hosts/
├── personal-laptop-nixos/
└── work-laptop-nixos/
```

Both can reuse:

```text
modules/
home/remarka/
```

while maintaining separate hardware configuration.

## 7. Stage everything

```fish
git add .
```

## 8. Check the new configuration

```fish
nix flake check
```

## 9. Build the new machine

```fish
sudo nixos-rebuild build \
  --flake ~/nixos-config#work-laptop-nixos
```

If successful:

```fish
sudo nixos-rebuild switch \
  --flake ~/nixos-config#work-laptop-nixos
```

After rebooting:

```fish
hostname
```

should return:

```text
work-laptop-nixos
```

# What should be shared between machines?

Good candidates for shared modules:

```text
modules/common.nix
modules/desktop.nix
modules/niri.nix
modules/maintenance.nix
modules/ssh.nix
modules/wireguard.nix
home/remarka/
```

Things that should normally remain machine-specific:

```text
hardware-configuration.nix
hostname
boot configuration if hardware differs
GPU-specific configuration
machine-specific drivers
machine-specific disks/filesystems
machine-specific services
```

If machines eventually require substantially different functionality, create additional reusable modules instead of adding many conditionals to `configuration.nix`.

For example:

```text
modules/
├── common.nix
├── development.nix
├── work.nix
├── gaming.nix
└── ...
```

Then each host imports only what it needs.

# Secrets

Do not commit plaintext secrets to this repository.

This includes:

* SSH private keys;
* WireGuard private keys;
* Wi-Fi passwords;
* API tokens;
* passwords;
* VPN configuration containing credentials.

SSH keys should remain under:

```text
~/.ssh/
```

and sensitive WireGuard profiles can remain managed locally by NetworkManager.

If reproducible secret management becomes necessary later, use a solution such as `sops-nix` or `agenix`.

# Design principle

The general rule for this repository is:

```text
flake.nix
    defines machines and dependencies

hosts/
    describes individual physical machines

modules/
    contains reusable operating-system configuration

home/
    contains reusable personal/user configuration
```

The goal is to keep the setup understandable rather than highly abstract.

A new machine should mostly consist of:

```text
new hardware-configuration.nix
+ small host configuration
+ existing shared modules
+ existing Home Manager configuration
```

This keeps the system reproducible while still allowing each machine to differ where necessary.
